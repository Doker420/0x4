# 0x4 · Telegram control panel

Веб-панель для подключения Pyrogram-сессий, настройки поведения агентов и управления ответами в целевом Telegram-чате. Панель отвечает **реплаем на входящее сообщение**; отправка GIF использует локальные медиа, список GIF в конфиге или настроенный GIPHY/Tenor-провайдер. Если медиа недоступно, агент отправит текст, а не промолчит.

> Приватный модуль DeepSeek не входит в репозиторий. Для генерации положите его в `vendor/Deepseek-API/` на сервере. Без него веб-панель запускается, а режим чата использует нейтральные короткие текстовые fallback-ответы и шаблоны; исходные сообщения доноров не копируются как ответы.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\\Scripts\\activate
python -m pip install -r requirements.txt
cp .env.example .env            # Windows: Copy-Item .env.example .env
python web_run.py
```

Откройте `http://127.0.0.1:8080`. При первом запуске создайте профиль владельца. Для Arena preview сервер по умолчанию слушает `0.0.0.0:8080`.

Для Telegram-бота (отдельно от чат-агентов) задайте `BOT_TOKEN` и `ADMIN_IDS` в `.env`, затем запустите `python bot.py`. Ответы бота и агента оформляются как reply к исходному сообщению.

## Подключить Telegram-аккаунт

1. В разделе **Аккаунты** укажите имя сессии, API ID/Hash из `my.telegram.org` и номер телефона.
2. Введите код, присланный Telegram; при включённой двухэтапной проверке укажите пароль 2FA.
3. Панель сохраняет авторизованную Pyrogram-сессию в `sessions/`, проверяет профиль и показывает статус. Также можно импортировать готовый Pyrogram-файл `.session`.
4. Для автоимпорта уже лежащих в `sessions/` файлов введите общий API ID/Hash один раз в разделе **Аккаунты** или задайте `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`, затем нажмите **Сохранить и проверить папку sessions/**. Действующие сессии добавятся автоматически; истёкшим всё ещё потребуется код Telegram/2FA. Проверка повторно использует уже подключённый клиент и не открывает второй Pyrogram SQLite-файл. Временная ошибка сети/SQLite или неподтверждённый локальный статус отображается как «проверка не удалась» и не переводит ранее авторизованную сессию в «нужен вход». Перед запуском фермы панель закрывает свои клиенты; во время работы фермы проверка/изменение `.session` блокируется.
5. Через **Настроить** редактируются прокси, persona, вероятность ответа, веса текста/GIF/стикеров/фото/голосовых и состояние аккаунта. Кнопка **2FA** устанавливает новый облачный пароль или меняет существующий по текущему паролю; секреты не сохраняются в базе.
6. При запуске ферма сначала использует прокси аккаунта; если он не отвечает, перебирает прокси других аккаунтов и сохраняет первый рабочий для этого аккаунта. Прямое соединение вместо прокси не включается. Если Telegram явно подтвердил, что сессия отозвана или аккаунт заблокирован, запись и локальные файлы сессии автоматически удаляются. При обычной сетевой ошибке или если запасных прокси нет сессия сохраняется, поскольку её авторизацию подтвердить нельзя.

Добавьте выбранный аккаунт в целевой чат, иначе Telegram не даст ему читать или отвечать на сообщения. Сессии, ключи, база, журналы и пользовательские данные игнорируются Git.

## Поведение и GIF

- **Поведение**: общие инструкции, задержки, вероятности ответов/реакций, общий интервал автономных сообщений, включение подхвата темы, модель DeepSeek, DeepThink, поиск и веса типов сообщений.
- **Ручное управление**: лента показывает сообщения людей в целевом чате, скрывая ботов и собственные аккаунты фермы. Выберите сообщение и аккаунт, введите свой текст — панель отправит его реплаем. Отдельный переключатель включает/выключает автоматические AI-ответы без остановки; входящие сообщения при этом продолжают попадать в ленту. Можно менять индивидуальную вероятность и роль аккаунта, паузы, общий шанс ответов и их направление, добавлять/убирать аккаунты, вступать/выходить из групп и комментировать посты по ссылке с отдельными фильтрами исходного текста; фильтры сохраняются, пока их явно не очистить.
- **Чат**: укажите ID целевого чата и, при необходимости, ID темы. Запускается только поведение без сценария: аккаунты отвечают участникам по инструкциям и истории как контексту, без подготовки AI-плана. Старые API-параметры сценариев и live-source отклоняются, а сохранённый режим нормализуется при запуске. До старта можно собрать обезличенную историю целевого или отдельного чата; источник только читается, публикации идут только в цель. При ответе в DM требуется отдельное подтверждение уведомления и согласия участников.
- **Тише по умолчанию**: на распознанный вопрос или просьбу отвечает один случайный аккаунт; обычные реплики получают ответ с вероятностью 25% (настраивается), а слабый офлайн-ответ пропускается вместо пустого согласия. GIF без подписи, аудиофайлы/голосовые сообщения и видео остаются в ленте, но не запускают автоответ. Дополнительный подхват темы выключен и включается отдельно. Автономная активность выключена; при включении общий интервал по умолчанию 300 секунд на действие всей фермы (Q&A может состоять из вопроса и ответа), а не отдельно на каждый аккаунт. Старые сохранённые значения прежних шумных настроек автоматически переводятся на эти значения; индивидуальные настройки аккаунтов сохраняются.
- **GIF**: задайте GIPHY или Tenor API key в разделе **Поведение** и проверьте поисковый превью. В ферме GIF загружается на сервер и отправляется как Telegram animation. Запрос идёт в случайный эндпоинт провайдера (`/gifs/random` у GIPHY, случайная позиция у Tenor), поисковая фраза собирается из случайных слов входящего сообщения, а уже отправленные гифки запоминаются общим списком — два аккаунта не отправят одну и ту же.
- **Музыка и видео из источников**: укажите ссылку на канал с музыкой (`@sad_tracky` по умолчанию) и канал с видео-приколами (`@prikoly` и т.п.), задайте долю в процентах. Панель открывает такие каналы только по явно указанной вами ссылке: если аккаунт чтения ещё не подписан, он подписывается на этот канал и читает последние посты. Файлы до 512 МБ скачиваются из источника во временную папку и заново загружаются в целевой чат выбранным аккаунтом — это не пересылка/копирование поста; подпись источника не добавляется. Временный файл удаляется после отправки. Список перемешивается и не повторяется, пока не закончится.
- **Устойчивое чтение лога**: панель читает вывод `farm.py` блоками и обрезает слишком длинные строки, поэтому одна огромная строка (например дамп объекта Pyrogram) больше не роняет читатель и не убивает ферму по BrokenPipe. Pyrogram в режиме `--debug` больше не включает пофайловый DEBUG-дамп (нужен явно: `FARM_PYROGRAM_DEBUG=1`), а `data/farm.log` автоматически урезается, чтобы не рос бесконечно.
- **Без повторов**: у фермы один общий список уже сказанного (последние 40 реплик, сохраняется между перезапусками). Каждая новая фраза сверяется с ним: если аккаунт собирается написать то же, что только что написал другой, реплика заменяется на свежий вариант или нейтральную фразу из пула, а не отправляется второй раз. То же правило действует для офлайн-заготовок (в том числе в режиме истории и при оживлении простоя), для подхвата темы и для генерации через DeepSeek — модель получает список уже прозвучавших реплик с прямым запретом их повторять.
- **Кубик и эмодзи-ответы**: в разделе «Поведение» настраиваются автоматические броски Telegram и ответы эмодзи. Во время работы фермы на странице «Чат» можно вручную отправить GIF, видео, музыку или выбранную анимацию кубика от активного аккаунта.
- **Контекст чата**: в разделе «Контекст» укажите публичную ссылку, invite-ссылку, `t.me/c/...` или ID чата. Аккаунту чтения достаточно обычного членства; права администратора/владельца не нужны. Для сбора истории в разделе «Чат» авто-вступление включено по умолчанию для публичного username или invite-ссылки; по числовому ID или `t.me/c/...` вступить нельзя, поэтому аккаунты должны уже быть участниками. Перед сбором подтвердите разрешение и уведомление участников. Глубина не ограничена; `0` собирает всю доступную историю. История обезличивается и используется как контекст, имена и стиль авторов не копируются.
- Файл `farm_config.json` необязателен и предназначен для локальных приватных настроек/совместимости. Начните с `farm_config.example.json`; не коммитьте реальный конфиг.

## Тесты и диагностика

```bash
python -m unittest discover -s tests -v
python -m py_compile bot.py farm.py web_run.py web/*.py
```

В разделе **Чат** доступны статус процесса и live-лог. Ошибки Telegram/GIF показываются в логе; сетевой тест прокси проверяет только доступность TCP-порта, не валидность прокси-логина.

## Секреты и безопасность

- Не коммитьте `.env`, `farm_config.json`, `sessions/*.session`, базу и данные чатов. Используйте `.env.example` только как шаблон.
- Загруженный архив содержал локальные секреты и Telegram session-файл. Архив исключён из текущего дерева; если он когда-либо попадал в GitHub или передавался третьим лицам, отзовите Telegram-сессии и замените связанные API/бот-ключи. Удаление файла из текущей версии не стирает его из истории Git.
- Авторизация панели нужна даже в доверенной сети; задайте сильный пароль и ограничьте доступ к порту.

## Airdrop-агент и отдельный Telegram-бот (`airdrop/` + `bot_airdrop.py`)

Самостоятельный модуль в этом же репозитории, не затрагивающий работу `bot.py` и `farm.py`:

- **Поиск кандидатов (`airdrop/discovery.py`, `airdrop/sources/`)** — опрашивает публичные read-only источники: DefiLlama (`/airdrops`, протоколы с TVL без токена, свежие раунды `/raises`), CoinGecko (тренды и свежие листинги), RSS крипто-СМИ, GitHub-трекеры и ваш локальный список `config/airdrops.json`. Ранжирует находки, штрафует скам-паттерны (`giveaway`, `send 0.1 ETH`, `seed phrase`) и складывает в SQLite (`data/airdrop/airdrop.sqlite3`).
- **Кошельки (`airdrop/wallet.py`)** — генерация и импорт ключей `eth_account`. Приватный ключ **никогда не хранится в открытом виде** и не попадает в логи: на диске лежит только JSON-конверт `AES-256-GCM` с ключом из `AIRDROP_KEY_PASSPHRASE` через `scrypt` и правами `0600`.
- **Проверка eligibility (`airdrop/eligibility.py`)** — проверяет ваши кошельки по публичным JSON-чекерам (`check_url` с `{address}`) или по ончейн-балансу (`ERC-20` / native через Web3 RPC). Ничего не подписывает.
- **Ончейн-действия под защитой (`airdrop/actions.py`)** — `claim()`, `swapExactETHForTokens` и перевод между собственными кошельками. По умолчанию включён `AIRDROP_DRY_RUN=1` (строится и оценивается только план без отправки в сеть). В боевом режиме действуют allow-лист контрактов (`config/contracts.json`), проверка наличия байткода на адресе, лимит на транзакцию (`AIRDROP_MAX_TX_VALUE_ETH`), суточный бюджет (`AIRDROP_DAILY_LIMIT_ETH`), потолок газа (`AIRDROP_MAX_GAS_GWEI`) и обязательная кнопка подтверждения в боте.
- **Отдельный Telegram-бот (`bot_airdrop.py`)** — работает на своём токене `AIRDROP_BOT_TOKEN` и отвечает только `AIRDROP_ADMIN_IDS`: `/status`, `/scan`, `/drops`, `/watch`, `/check`, `/wallets`, `/newwallet`, `/claim`, `/swap`, `/actions`, `/settings`, `/logs` + inline-кнопки «В работу / Скип / Проверить кошельки / Подтвердить».

### Быстрый деплой на ваш VPS (одной командой)

```bash
git clone https://github.com/Doker420/0x4.git /opt/0x4
cd /opt/0x4
sudo bash deploy/install.sh
```

Скрипт сам создаст `.venv`, поставит `requirements-airdrop.txt`, подготовит `.env` (права `600`) со сгенерированной `AIRDROP_KEY_PASSPHRASE`, скопирует `config/airdrops.json` и `config/contracts.json` из шаблонов, прогонит тесты и зарегистрирует systemd-сервисы `airdrop-agent` и `airdrop-bot`.

Дальше останется только прописать в `/opt/0x4/.env` токен нового бота от `@BotFather` и свой Telegram ID:

```ini
AIRDROP_BOT_TOKEN=123456:ABC...
AIRDROP_ADMIN_IDS=123456789
```

и перезапустить бота:

```bash
sudo systemctl restart airdrop-bot airdrop-agent
sudo journalctl -u airdrop-agent -u airdrop-bot -f
```

Или через Docker Compose:

```bash
cp .env.example .env   # заполните AIRDROP_BOT_TOKEN, AIRDROP_ADMIN_IDS, AIRDROP_KEY_PASSPHRASE
docker compose -f deploy/docker-compose.yml up -d --build
```

```bash
# Разовый прогон поиска (офлайн по фикстурам / онлайн по публичным API)

```
