# 0x4 · Telegram control panel

Веб-панель для подключения Pyrogram-сессий, настройки поведения агентов и управления ответами в целевом Telegram-чате. Панель отвечает **реплаем на входящее сообщение**; отправка GIF использует локальные медиа, список GIF в конфиге или настроенный GIPHY/Tenor-провайдер. Если медиа недоступно, агент отправит текст, а не промолчит.

> Приватный модуль DeepSeek не входит в репозиторий. Для генерации положите его в `vendor/Deepseek-API/` на сервере. Без него веб-панель запускается, а режим чата использует нейтральные короткие текстовые fallback-ответы и шаблоны; исходные сообщения доноров не копируются как ответы.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\\Scripts\\activate
python -m pip install -r requirements.txt
cp .env.example .env            # Windows: Copy-Item .env.example .env
python web_run.py
```

Откройте `http://127.0.0.1:8080`. При первом запуске создайте профиль владельца. Для Arena preview сервер по умолчанию слушает `0.0.0.0:8080`.

Для Telegram-бота (отдельно от чат-агентов) задайте `BOT_TOKEN` и `ADMIN_IDS` в `.env`, затем запустите `python bot.py`. Ответы бота и агента оформляются как reply к исходному сообщению.

## Подключить Telegram-аккаунт

1. В разделе **Аккаунты** укажите имя сессии, API ID/Hash из `my.telegram.org` и номер телефона.
2. Введите код, присланный Telegram; при включённой двухэтапной проверке укажите пароль 2FA.
3. Панель сохраняет авторизованную Pyrogram-сессию в `sessions/`, проверяет профиль и показывает статус. Также можно импортировать готовый Pyrogram-файл `.session`.
4. Для автоимпорта уже лежащих в `sessions/` файлов введите общий API ID/Hash один раз в разделе **Аккаунты** или задайте `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`, затем нажмите **Сохранить и проверить папку sessions/**. Действующие сессии добавятся автоматически; истёкшим всё ещё потребуется код Telegram/2FA. Проверка повторно использует уже подключённый клиент и не открывает второй Pyrogram SQLite-файл. Временная ошибка сети/SQLite или неподтверждённый локальный статус отображается как «проверка не удалась» и не переводит ранее авторизованную сессию в «нужен вход». Перед запуском фермы панель закрывает свои клиенты; во время работы фермы проверка/изменение `.session` блокируется.
5. Через **Настроить** редактируются прокси, persona, вероятность ответа, веса текста/GIF/стикеров/фото/голосовых и состояние аккаунта. Кнопка **2FA** устанавливает новый облачный пароль или меняет существующий по текущему паролю; секреты не сохраняются в базе.

Добавьте выбранный аккаунт в целевой чат, иначе Telegram не даст ему читать или отвечать на сообщения. Сессии, ключи, база, журналы и пользовательские данные игнорируются Git.

## Поведение и GIF

- **Поведение**: общие инструкции, задержки, вероятности ответов/реакций, модель DeepSeek, DeepThink, поиск и веса типов сообщений.
- **Чат**: укажите ID группы и, при необходимости, ID темы; подтвердите разрешение на автоматизацию и уведомление участников (выбранные аккаунты должны уже состоять в чате). По умолчанию выбрано «Без сценария»: общая тема и стартовое сообщение не нужны; используются сохранённые настройки аккаунтов (persona, инструкции из раздела «Поведение», вероятность, задержку и медиа), включая отдельно включённую автономную активность. Сценарный диалог и ответы участникам можно выбрать отдельно.
- **GIF**: задайте GIPHY или Tenor API key в разделе **Поведение** и проверьте поисковый превью. В ферме GIF загружается на сервер и отправляется как Telegram animation.
- **Контекст чата**: в разделе «Контекст» укажите публичную ссылку, invite-ссылку, `t.me/c/...` или ID чата. Аккаунт чтения может быть обычным участником; права администратора/владельца не нужны. По умолчанию выбранные аккаунты должны уже состоять в источнике. Если участники дали разрешение на вступление, можно явно включить авто-вступление выбранных аккаунтов: оно работает по публичному username или invite-ссылке. Числовой ID и `t.me/c/...` сами по себе не дают права вступить — понадобится invite-ссылка или username. Перед сбором и (если выбрано) вступлением подтвердите, что объявили участникам об автоматизации. При подтверждении разрешения сохраняются до 300 последних сообщений с обезличенными авторами; по желанию локально скачиваются не более 10 файлов до 3 МБ каждый (суммарно до 30 МБ на чат). В разделе «Чат» можно отдельно указать источник истории по ID/ссылке (по умолчанию он совпадает с целевым чатом); архив собирается до запуска и используется как контекст в другом целевом чате. Сессии сопоставляются 1:1 по выбранному порядку с анонимными участниками в порядке их первого появления; каждый бот получает только сообщения своего назначенного участника. Имена и стиль реальных людей не копируются — боты говорят в синтетических ролях. Историю источника можно удалить со страницы контекстов; это не удаляет историю отдельного чата-назначения. Ферма хранит состояние отдельно по ID целевого чата и использует отдельную DeepSeek-сессию для каждой пары «чат/аккаунт». Текст и медиа источника не перепубликуются автоматически.
- **Режимы в разделе «Чат»**: «Без сценария» запускает обычное поведение аккаунтов — без сценарной темы, стартового сообщения, архивного контекста или цепочки диалога; сохранённая настройка автономной активности продолжает учитываться отдельно. «Диалог аккаунтов» ведёт последовательную дискуссию по заданной теме; «Диалог и ответы» запускает оба поведения одновременно; «Диалог по истории чата» перед запуском собирает выбранный источник и строит на нём цепочку с отдельными синтетическими ролями. Архив используется как содержание, не как идентичность: на каждом восьмиходовом этапе берётся одна обезличенная реплика-основа, но реальные авторы не имитируются. В новом режиме по умолчанию 8 ходов; `0` продолжает до ручной остановки. Для чтения достаточно обычного участника — права администратора не требуются; для отсутствующих в источнике аккаунтов можно явно запустить вступление при наличии разрешения и username/invite-ссылки. Перед запуском нужно подтвердить, что вы объявили автоматизацию участникам. В объединённом режиме сообщения выбранной темы сохраняются как контекст, а на вопрос или явную просьбу (знак `?` не обязателен) реплаем отвечает один случайно выбранный аккаунт; вероятность ответа и медиа настроены отдельно у аккаунтов. Обычные реплики пополняют контекст, но не вызывают ответ. В live-логе видны распознавание вопроса, выбранная вероятность, задержка и результат отправки реплая. Аккаунты диалога чередуются, могут добавлять короткие анекдоты и медиа. При достижении лимита ходов тематический диалог завершается, ответы на вопросы остаются активны до ручной остановки. «Рулетка» — отдельный режим и публикует случайные числа из заданного диапазона/списка. Для сценариев задаются число ходов, паузы и длинные перерывы; `0` ходов означает работу до ручной остановки.
- Для сценариев выберите минимум два аккаунта. Стартовая тема может публиковаться в чат, но только первый ход этапа отзывается на неё или на историческую реплику; каждый следующий аккаунт продолжает предыдущую мысль и добавляет следующий пункт цепочки: критерий → компромисс → проверка → вывод. Аккаунты не должны независимо отвечать на исходную тему. Общие зацикленные фразы отбрасываются; при повторе LLM делает одну попытку заново, затем используется предметный локальный fallback. GIF, стикеры, фото и голосовые отправляются по заданным весам с сохранением reply-to. Используйте такие сценарии только в группе, которой управляете, и предупредите участников об автоматизации. Без DeepSeek bridge диалог использует контекстные шаблоны; для актуальных новостей нужен bridge с включённым веб-поиском.
- Файл `farm_config.json` необязателен и предназначен для локальных приватных настроек/совместимости. Начните с `farm_config.example.json`; не коммитьте реальный конфиг.

## Тесты и диагностика

```bash
python -m unittest discover -s tests -v
python -m py_compile bot.py farm.py web_run.py web/*.py
```

В разделе **Чат** доступны статус процесса и live-лог. Ошибки Telegram/GIF показываются в логе; сетевой тест прокси проверяет только доступность TCP-порта, не валидность прокси-логина.

## Секреты и безопасность

- Не коммитьте `.env`, `farm_config.json`, `sessions/*.session`, базу и данные чатов. Используйте `.env.example` только как шаблон.
- Загруженный архив содержал локальные секреты и Telegram session-файл. Архив исключён из текущего дерева; если он когда-либо попадал в GitHub или передавался третьим лицам, отзовите Telegram-сессии и замените связанные API/бот-ключи. Удаление файла из текущей версии не стирает его из истории Git.
- Авторизация панели нужна даже в доверенной сети; задайте сильный пароль и ограничьте доступ к порту.
